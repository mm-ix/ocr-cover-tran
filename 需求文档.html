屏幕截图翻译工具 需求文档

文档版本：v1.0 ｜ 创建：2026-11-04 ｜ 状态：待评审 目标平台：Windows 10 19044+ / Windows 11，x64 绿色免安装 代号：ShotTrans（暂定）

1. 背景

用户需要一个和网易有道截图翻译、UU 加速器游戏翻译同形态的工具：

按快捷键 → 拖框选择屏幕区域 → 译文出现在原文字位置、盖住原文 → 用完即消失。

现有开源方案都不满足这个形态：

方案 不满足的点
LunaTranslator（14k★） OCR 是「选区常驻 + 周期识别」，不是一次性；关闭要单独一步
pot（19.3k★，已归档） 图片翻译输出新图；截图翻译结果在独立窗口，无原位覆盖
BallonsTranslator（5.2k★） 必须先有图片文件，无截图入口
manga-image-translator（10.5k★） CLI / Web 服务，无 GUI 热键
LightTranslate（0★） 形态正确，但单屏假设、半年前停更、无设置界面

结论：自研一个轻量外壳（约 1,500 行 C#），覆盖层自写，OCR 与翻译复用成熟组件。

2. 目标与非目标

2.1 目标

  1. 一次热键，从框选到看到译文 ≤ 2 秒（本地 OCR + 云端翻译）。
  2. 译文按原文字块位置覆盖，字号自适应、不溢出原框。
  3. 用完即走：Esc / 右键 / 点击外部立刻消失，不留常驻窗口。
  4. 翻译走用户自己的 OpenAI 兼容接口（ccx 网关 / 阿里百炼 / DeepSeek 任一），可随时切换。
  5. 绿色版：解压即用，不写注册表，不装运行时。

2.2 非目标（本期不做）

  • ❌ 实时/连续翻译（LUNA 那种视频字幕模式）
  • ❌ 手机端、macOS、Linux
  • ❌ 多语言界面（只做简体中文 UI）
  • ❌ 漫画批量翻译、PDF 翻译、文档翻译
  • ❌ 账号体系、云同步、翻译记忆库

3. 用户与场景

场景 描述 关键诉求
英文软件界面 打开一个英文软件，看不懂菜单/设置项 快、不打断操作
游戏 / 视频硬字幕 无字幕或外语字幕 位置贴合，不挡其他画面
报错 / 技术文档 截图里有代码、命令、术语 代码和专有名词不许乱翻
网页 / PDF 图表 只有图片，选不中文字 保留版式，能对照原文

使用频率预期：每天 5~30 次，单次停留 3~30 秒。

4. 核心流程

① 全局热键（默认 Ctrl+Alt+X）
      ↓
② 屏幕变暗，进入框选；拖出矩形（显示尺寸像素）
      ↓
③ 截图该区域（原分辨率）
      ↓
④ 本地 OCR → 得到每个文字块的文本 + 边界框
      ↓
⑤ 批量翻译（按块合并成一次请求，保留顺序）
      ↓
⑥ 覆盖层出现：每个框内绘制译文，背景取原图局部颜色
      ↓
⑦ 阅读中：按住 Space 临时隐藏译文看原文
      ↓
⑧ Esc / 右键 / 点击外部 → 全部销毁

异常路径

  • OCR 无文字 → 提示「没识别到文字」，1 秒后自动关闭
  • 翻译失败 → 覆盖层显示原文 + 顶部红色提示「翻译失败：<原因>」，按 R 重试
  • 区域过小（< 40×20 px）→ 忽略，不进入流程

5. 功能需求

P0（不做完不能用）

编号 需求 验收要点
F-01 全局热键触发框选，可改键 在任意前台程序（含全屏 borderless 游戏）按下即响应
F-02 框选交互：全屏半透明遮罩、实时显示选区尺寸、右键/Esc 取消 显示 宽×高，取消后无残留
F-03 截图：按物理像素抓取选区 125%/150% 缩放下框选范围与截图范围一致
F-04 本地 OCR：Windows.Media.Ocr 中文、英文识别可用；返回逐行文本 + 边界框
F-05 翻译：OpenAI 兼容 /chat/completions 配置 base_url / api_key / model 后可用；超时 20s
F-06 原位覆盖：每块文字画在原边界框内 译文不超出框、不重叠邻块；框过小自动缩小字号
F-07 覆盖层样式：背景取原图局部主色，文字色按背景亮度自动黑/白 深色底出白字、浅色底出黑字，肉眼可读
F-08 覆盖层不拦截鼠标 覆盖期间可以点下面的窗口（除 Esc 外不响应键盘）
F-09 关闭：Esc / 右键 / 点击外部 三者任一都能销毁，且可立即再次触发
F-10 对比：按住 Space 显示原文 松开恢复译文；不重新请求翻译
F-11 翻译结果可复制 Ctrl+C 复制全部译文（按阅读顺序拼接）

P1（第一版应该有）

编号 需求 说明
F-12 多显示器支持 在副屏框选、跨屏框选都要正常
F-13 高 DPI 适配（100%~200%） Win10 每屏不同缩放也要正确
F-14 截图时排除自己 用 SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)，避免覆盖层被二次识别
F-15 设置界面 热键、接口、模型、字体大小范围、背景不透明度、超时
F-16 术语保护 用户词表 + 正则：[A-Za-z_][A-Za-z0-9_]* 代码标识符不进翻译；术语按表替换
F-17 托盘常驻 + 开机自启开关 托盘右键：截图翻译 / 设置 / 退出
F-18 历史记录（本地） 最近 200 条：缩略图 + 原文 + 译文，可复制/删除；存 SQLite
F-19 失败可重试 顶部提示条 + R 重试（复用已截图的图，不重截）

P2（以后再说）

编号 需求
F-20 PaddleOCR（PP-OCRv5）作为第二引擎，中文小字/复杂背景更准
F-21 日文竖排识别与竖排回填
F-22 拖入图片文件直接翻译（复用同一套渲染）
F-23 划词翻译（选中文本+热键）
F-24 多模态兜底：OCR 失败时整块图丢给 qwen-vl 直接出译文与坐标

6. 非功能需求

类别 指标
性能 热键→覆盖出现：本地 OCR ≤ 300ms，翻译 ≤ 1.5s（20 行以内），端到端 P95 ≤ 2.5s
体积 绿色目录 ≤ 40 MB（自包含 .NET，不含 OCR 额外模型）
依赖 Windows 10 19044+；无需安装 .NET 运行时；无需管理员权限
隐私 截图与 OCR 结果只在内存；仅「文字」发往用户配置的翻译接口；不上传图片（P2 多模态除外，且需明确开关）
稳定性 连续触发 100 次不崩溃、不残留窗口；异常退出后可再次启动
兼容性 普通窗口 / 全屏 borderless / 多屏 / 远程桌面（RDP 内可用）
已知限制 独占全屏（Exclusive Fullscreen）游戏无法截取 → 提示改用无边框

7. 技术方案（选型说明）

语言/框架   C# / .NET 8 + WPF（自包含发布，单目录绿色）
热键        RegisterHotKey（WH_KEYBOARD_LL 作为备用）
框选窗口    全屏 WS_EX_LAYERED + WS_EX_TOOLWINDOW，每屏一个
截图        BitBlt（GDI）优先；失败回退 Windows.Graphics.Capture
OCR         Windows.Media.Ocr（系统自带，零依赖）
            备选 PaddleOCR（onnxruntime，P2）
翻译        HttpClient → OpenAI 兼容 /chat/completions
覆盖渲染    逐像素透明窗口（UpdateLayeredWindow）+ DirectWrite 排版
            · 字号：从 max 开始二分，直到文本块宽高 ≤ 原框
            · 背景：原图局部中位色，圆角矩形
            · 点击穿透：WS_EX_TRANSPARENT + WS_EX_NOACTIVATE
配置        %APPDATA%\ShotTrans\config.json（或程序目录，绿色优先）

为什么不用 Tauri/Electron：覆盖层要逐像素透明 + 点击穿透 + 精确文字排版，原生窗口 API 一步到位；JS 壳反而要绕。

8. 界面与交互细节

框选态
  · 全屏暗化 40%，选区高亮
  · 十字光标，实时显示「640 × 220」
  · Esc / 右键取消

结果态
  · 无边框、无标题栏、无阴影
  · 每个文字块：圆角背景 + 译文（居中/左对齐可选）
  · 顶部悬浮小条：显示「已翻译 12 块 · 1.2s」+ 提示「Space 看原文 / Esc 关闭」
  · 3 秒后小条自动淡出，只留译文

设置页（单页，两栏）
  左：热键、OCR 语言、字体大小上下限、背景不透明度
  右：翻译接口（base_url / key / model / 温度）、术语表

9. 验收清单（逐条可测）

  • ☐ 按下热键，屏幕变暗并进入框选
  • ☐ 拖出一个区域，松手后 ≤ 2.5s 出现译文
  • ☐ 译文在原文位置上，不溢出、不压到相邻块
  • ☐ 深色背景出白字，浅色背景出黑字
  • ☐ 覆盖期间点击下方窗口能正常操作
  • ☐ 按住 Space 看到原文，松开回到译文
  • ☐ Esc / 右键 / 点外部，三种方式都能关闭
  • ☐ 关闭后可立刻再次触发，不残留任何窗口
  • ☐ 125% 缩放下框选与截图范围一致
  • ☐ 副屏框选正常（多显示器）
  • ☐ 翻译接口填错时，提示明确且可按 R 重试
  • ☐ 代码标识符（如 GetProcAddress）不被翻译
  • ☐ 连续触发 50 次无崩溃、无内存持续增长

11. 风险与对策

风险 影响 对策
Windows OCR 对小字/复杂背景识别差 译文不全 P0 先接受；P2 挂 PaddleOCR；极端情况用多模态兜底
字号自适应后中文换行难看 观感差 允许"整体缩小 + 2 行截断 + 省略号"，并支持手动调字号
独占全屏游戏截不到 场景缺失 首次失败提示改用无边框窗口（Borderless）
翻译接口延迟高 体感慢 支持并发分块请求 + 缓存相同文本（同一块重复出现直接复用）
用户环境无 .NET 起不来 自包含发布（含运行时），目录大一点但零依赖
